# TechParts 3D — Backend, приватная админ-панель и Excel (.xlsx)

Этот документ описывает текущую реализацию и ручную настройку. До завершения шагов с Supabase сайт остаётся в демонстрационном режиме: старые записи хранятся в `localStorage` конкретного браузера. **Не вводи настоящие персональные данные, пока не завершена конфигурация и проверка доступа.**

## Что добавлено в проект

* `admin.html` — отдельная административная панель с входом по e-mail и паролю.
* `admin.js` — авторизация, просмотр заявок, изменение статуса, удаление, редактирование набора полей.
* `admin.css` — адаптивный интерфейс административной панели.
* `supabase/schema.sql` — таблицы и политики Row Level Security (RLS).
* `supabase-config.js` — пустые поля конфигурации. В него нельзя помещать service role key или пароль базы данных.
* Экспорт из админ-панели в настоящий `.xlsx` с листами «Übersicht», «Anfragen» и «Formularfelder», таблицей, фильтрами, закреплённой строкой заголовка, форматированием статусов и напоминанием о конфиденциальности.
* Публичная форма сможет загружать поля из `form\\\\\\\_fields`; поля, подписи, тип, обязательность, активность, варианты и порядок управляются в админ-панели.

## 1\. Создай бесплатный проект Supabase

1. Открой [https://supabase.com/](https://supabase.com/) и создай аккаунт/проект на Free-плане.
2. Выбери сильный уникальный пароль базы данных и сохрани его отдельно. Он не требуется на сайте и не должен попадать в GitHub.
3. В панели проекта открой **SQL Editor → New query**.
4. Скопируй весь файл `supabase/schema.sql`, вставь в SQL Editor и выполни запрос.
5. Убедись, что таблицы `admin\\\\\\\_users`, `form\\\\\\\_fields` и `inquiries` созданы, а в `form\\\\\\\_fields` появились семь начальных полей.

Free-проекты могут приостанавливаться после периода низкой активности; бесплатный тариф подходит для обучения и портфолио, но не является SLA для производственной системы. Проверь текущие квоты на [https://supabase.com/pricing](https://supabase.com/pricing).

## 2\. Добавь публичные параметры подключения

В Supabase открой **Project Settings → API** (название раздела может отличаться). Скопируй:

Project URL:** https://dnszvsicaxhefvdyebql.supabase.co
* **Publishable key:** получи актуальный ключ в Supabase → Project Settings → API Keys. Для публичного файла используй только ключ с префиксом sb_publishable_. Секретные ключи здесь не публикуются.

В файле `supabase-config.js` вставь их в кавычки:

```js
export const SUPABASE\\\\\\\_URL = 'https://YOUR-PROJECT.supabase.co';
export const SUPABASE\\\\\\\_ANON\\\\\\\_KEY = 'YOUR\\\\\\\_PUBLIC\\\\\\\_ANON\\\\\\\_OR\\\\\\\_PUBLISHABLE\\\\\\\_KEY';
```

Публичный anon/publishable key может находиться в клиентском коде **только потому, что доступ должен ограничиваться RLS-политиками**. Никогда не помещай в сайт `service\\\\\\\_role` key, секретный API key или пароль БД. Если сомневаешься, не публикуй значения — сначала проверь их тип.

## 3\. Создай единственную учётную запись администратора

1. В Supabase открой **Authentication → Users → Add user**.
2. Создай пользователя со своим e-mail и задай уникальный пароль непосредственно в Supabase. Сохрани его в KeePassXC. Никогда не записывай действующий пароль в публичную документацию.

   ---
3. Найди UUID пользователя в Supabase → Authentication → Users и подставь его в SQL локально. 

   ---
4. В **SQL Editor** выполни запрос, заменив UUID на UUID своего пользователя:

```sql
insert into public.admin\\\\\\\_users (user\\\\\\\_id)
values ('ВСТАВЬ-СЮДА-UUID-ТВОЕГО-ПОЛЬЗОВАТЕЛЯ');
```

Не добавляй неизвестных пользователей. В административной панели нет публичной регистрации. Для выхода используется кнопка «Abmelden».

## 4\. Запусти и проверь локально

Из каталога `techparts3d` запусти локальный сервер:

```powershell
python -m http.server 8000
```

Открой [http://localhost:8000/](http://localhost:8000/). Перейди в `#request` и проверь, что активные поля загружаются из базы. Затем открой [http://localhost:8000/admin.html](http://localhost:8000/admin.html), войди и проверь:

* видны только твои заявки;
* можно изменить статус, например `Neu` → `In Bearbeitung`;
* можно изменить подписи, обязательность, порядок или варианты выбора поля;
* после сохранения обнови публичную страницу в другом окне/вкладке: поля должны соответствовать конфигурации;
* экспорт открывается как `.xlsx`, а не CSV, и в книге есть три листа.

**Тест доступа (обязательный):** открой публичный сайт в режиме инкогнито и отправь тестовую заявку. В админ-панели она должна быть видна после входа. В инкогнито открой `admin.html`: без входа заявки недоступны. Для проверки RLS также попробуй с клиентской консолью или API, что анонимный запрос `SELECT` к `inquiries` получает отказ/пустой результат. Не считай настройку проверенной, пока не проверишь именно отказ в чтении.





**401 (Unauthorized)**



Сервер отклонил анонимный запрос на чтение заявок.







**42501 — permission denied for table inquiries**



База данных отказала в доступе к таблице inquiries.







**data: null**



Запрос не вернул данные заявок.

## Границы защиты / чего пока нет

* Данные в `inquiries` читаются/изменяются из панели только зарегистрированным пользователем, чья UUID вручную внесена в `admin\\\\\\\_users`, если SQL-схема и RLS успешно применены.
* Публичная форма намеренно может **только вставлять** новые заявки и не может читать/изменять/удалять заявки. Этот публичный endpoint всё ещё можно атаковать спамом; текущий размер записи ограничен, но rate limit/CAPTCHA пока не реализованы.
* Настоящая конфиденциальность также зависит от безопасности e-mail, пароля, аккаунта GitHub, устройства и Supabase. Включи MFA, если доступно, и не используй общий компьютер.
* Экспорт `.xlsx` загружается в папку загрузок твоего компьютера. Он больше не защищён серверной RLS после скачивания. Храни файл на собственном защищённом устройстве, не загружай в публичные репозитории и не пересылай без необходимости. Для особо важных данных можно использовать шифрование устройства/файла отдельно.
* Код не реализует автоматические резервные копии, уведомления по e-mail, защиту от ботов, ограничение частоты запросов или аудит каждого изменения. Это последующие этапы.
* Бесплатные тарифы и условия сервисов меняются. Не используй эту учебную конфигурацию для реальных чувствительных данных/производственной деятельности без отдельной проверки безопасности и правовых требований.

## Воспроизводимость
